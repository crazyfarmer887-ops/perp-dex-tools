# 수수료 절감 기능 제안서

현재 봇은 이미 maker 주문(POST_ONLY)을 사용하여 수수료를 최소화하고 있습니다. 볼륨 거래 시 수수료를 더 절감할 수 있는 기능들을 제안합니다.

## 1. 포지션 네팅 (Position Netting) 기능

### 개념
여러 개의 개별 포지션을 하나로 합쳐서 총 거래 횟수를 줄이는 기능입니다.

### 구현 방법
- 현재 활성 포지션과 새로운 오픈 주문의 방향을 확인
- 반대 방향의 포지션이 있으면 기존 포지션을 먼저 상쇄
- 남은 수량만 새로 오픈 주문으로 처리

### 예시
```
현재 포지션: +0.3 ETH (롱)
새 오픈 주문: -0.2 ETH (숏)
→ 결과: +0.1 ETH만 남기고, 0.2 ETH는 네팅으로 처리 (2번의 거래 → 1번의 거래)
```

### 수수료 절감 효과
- 거래 횟수 감소로 총 수수료 절감
- 특히 활성 포지션이 많을 때 효과적

---

## 2. 스마트 클로즈 주문 관리 (Smart Close Order Management)

### 개념
가격이 유리하게 움직일 때 기존 클로즈 주문을 취소하고 더 유리한 가격에 재주문하는 기능입니다.

### 구현 방법
- 주기적으로 활성 클로즈 주문의 가격을 확인
- 현재 시장 가격이 기존 클로즈 주문 가격보다 유리하면:
  1. 기존 클로즈 주문 취소
  2. 더 유리한 가격에 새 클로즈 주문 (같은 take-profit % 유지)
- maker 주문 유지로 수수료 구조 유지

### 예시
```
기존 클로즈 주문: $2000.80 (take-profit 0.04%)
현재 시장 가격: $2000.50
→ 새 클로즈 주문: $2000.50 * 1.0004 = $2000.58
→ 수수료는 동일하지만 더 빠른 체결 가능성
```

### 수수료 절감 효과
- 직접적인 수수료 절감은 아니지만, 더 빠른 체결로 자본 회전율 향상
- 불필요한 주문 취소/재주문 최소화

---

## 3. 주문 집계 (Order Aggregation) 기능

### 개념
짧은 시간 내에 여러 개의 작은 주문을 하나의 큰 주문으로 합치는 기능입니다.

### 구현 방법
- 새로운 오픈 주문 요청이 들어오면 일정 시간(예: 1-3초) 대기
- 대기 중 추가 주문 요청이 있으면 합침
- 시간 초과 후 집계된 주문을 한 번에 실행

### 예시
```
1초 내 3개의 주문 요청:
- 0.1 ETH @ $2000
- 0.1 ETH @ $2000.10  
- 0.1 ETH @ $2000.20
→ 집계: 0.3 ETH @ 평균가 $2000.10
→ 3번의 거래 → 1번의 거래
```

### 수수료 절감 효과
- 거래 횟수 감소로 총 수수료 절감
- 단, 체결 지연 가능성 있음

## 4. Maker 수수료 리베이트 최적화

### 개념
거래소의 maker 수수료 리베이트 프로그램을 최대한 활용하는 기능입니다.

### 구현 방법
- 거래소별 maker 리베이트 구조 파악
- 리베이트 한도나 최소 거래량 요구사항 확인
- 주문 크기와 타이밍을 리베이트 최적화에 맞춤

### 예시
```
거래소 A: 일일 거래량 $10,000 이상 시 maker 리베이트 0.01%
→ 주문 크기와 빈도를 조절하여 리베이트 한도 달성
```

### 수수료 절감 효과
- 리베이트로 실제 수수료 부담 감소
- 장기적으로 상당한 절감 효과

---

## 5. 부분 체결 최적화 (Partial Fill Optimization)

### 개념
부분 체결된 주문을 더 효율적으로 처리하는 기능입니다.

### 현재 문제점
- 부분 체결 시 남은 수량에 대해 새 주문을 다시 생성
- 이로 인해 불필요한 주문 생성 가능

### 구현 방법
- 부분 체결된 주문의 남은 수량을 추적
- 체결된 부분만 클로즈 주문 생성
- 남은 수량은 기존 오픈 주문 유지 또는 조정

### 수수료 절감 효과
- 불필요한 주문 생성 감소
- 주문 관리 효율성 향상

---

## 6. 수수료 인식 그리드 전략 (Fee-Aware Grid Strategy)

### 개념
수수료 구조를 고려하여 그리드 간격을 동적으로 조정하는 기능입니다.

### 구현 방법
- 거래소별 maker/taker 수수료 구조 파악
- take-profit %가 수수료를 충분히 커버하는지 확인
- 수수료가 높은 거래소는 그리드 간격을 넓혀 수익성 확보

### 예시
```
거래소 A: maker 0.02%, taker 0.05%
거래소 B: maker 0.01%, taker 0.03%

→ 거래소 A에서는 take-profit을 0.05% 이상으로 설정
→ 거래소 B에서는 take-profit을 0.03% 이상으로 설정
```

### 수수료 절감 효과
- 수수료를 고려한 최적의 take-profit 설정
- 손익분기점 이하의 거래 방지

---

## 7. 교차 거래소 수수료 비교 (Cross-Exchange Fee Comparison)

### 개념
여러 거래소의 수수료를 비교하여 가장 유리한 거래소를 선택하는 기능입니다.

### 구현 방법
- 지원하는 거래소들의 현재 수수료 구조 비교
- 거래량, 리베이트, VIP 레벨 등을 고려한 실제 수수료 계산
- 가장 유리한 거래소 자동 선택 또는 추천

### 수수료 절감 효과
- 항상 가장 낮은 수수료의 거래소 선택
- 장기적으로 상당한 절감 효과

---

## 8. 시간 기반 수수료 최적화 (Time-Based Fee Optimization)

### 개념
일부 거래소가 특정 시간대에 낮은 수수료를 제공하는 경우를 활용하는 기능입니다.

### 구현 방법
- 거래소별 시간대별 수수료 구조 확인
- 낮은 수수료 시간대에 거래 집중
- 높은 수수료 시간대에는 거래량 감소

### 수수료 절감 효과
- 시간대별 수수료 차이 활용
- 단, 모든 거래소가 지원하지 않을 수 있음

---

## 우선순위 추천

### 즉시 구현 가능 (높은 효과)
1. **포지션 네팅** - 구현 난이도 중간, 효과 높음
2. **스마트 클로즈 주문 관리** - 구현 난이도 낮음, 효과 중간
3. **부분 체결 최적화** - 구현 난이도 낮음, 효과 중간

### 중기 구현 (중간 효과)
4. **주문 집계** - 구현 난이도 중간, 효과 중간
5. **수수료 인식 그리드 전략** - 구현 난이도 낮음, 효과 중간

### 장기 구현 (높은 효과, 복잡)
6. **Maker 수수료 리베이트 최적화** - 구현 난이도 높음, 효과 높음
7. **교차 거래소 수수료 비교** - 구현 난이도 높음, 효과 높음
8. **시간 기반 수수료 최적화** - 구현 난이도 중간, 효과 낮음

---

## 구현 시 고려사항

1. **리스크 관리**: 수수료 절감이 거래 전략의 안정성을 해치지 않도록 주의
2. **복잡도 증가**: 기능 추가로 인한 코드 복잡도 증가 관리
3. **테스트**: 각 기능의 정확한 동작 검증 필요
4. **모니터링**: 수수료 절감 효과를 측정할 수 있는 로깅 추가
