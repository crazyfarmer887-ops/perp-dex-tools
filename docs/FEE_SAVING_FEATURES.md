# 수수료 절감 기능 제안서

## 현재 로직 분석

현재 봇은 다음과 같은 방식으로 작동합니다:
- **Maker 주문**: 대부분의 주문이 `post_only=True`로 설정되어 maker 수수료를 받습니다
- **Boost 모드**: Maker로 열고 Taker로 닫는 방식 (aster, backpack만 지원)
- **Hedge 모드**: 두 거래소에서 동시 거래

## 제안하는 수수료 절감 기능

### 1. **스마트 주문 집계 (Order Aggregation)**
**목적**: 여러 작은 주문을 큰 주문으로 집계하여 수수료 절감

**구현 방법**:
- 여러 개의 작은 close 주문이 비슷한 가격에 있을 때, 하나의 큰 주문으로 통합
- 통합된 주문이 체결되면 원래 주문들을 모두 취소 처리
- `max-orders` 제한 내에서 주문 수를 줄여 관리 비용 절감

**절감 효과**: 
- 주문 관리 오버헤드 감소
- 일부 거래소에서 주문 수에 따른 추가 수수료 절감 가능

### 2. **Maker 수수료 리베이트 최적화**
**목적**: Maker 수수료 리베이트를 최대화하는 주문 전략

**구현 방법**:
- 거래소별 maker 리베이트 비율 추적
- 리베이트가 높은 거래소에서 더 많은 볼륨 집중
- 주문 크기와 리베이트 관계 분석

**절감 효과**:
- Maker 리베이트로 실제 수수료가 음수가 될 수 있음 (예: -0.01% 리베이트)

### 3. **동적 주문 크기 최적화**
**목적**: 수수료 구조에 맞춰 최적 주문 크기 계산

**구현 방법**:
- 거래소별 수수료 구조 분석 (maker/taker, 고정/비례)
- 최소 수수료를 위한 최적 주문 크기 계산
- 주문 크기를 동적으로 조정

**절감 효과**:
- 불필요한 작은 주문으로 인한 수수료 낭비 방지
- 최적 주문 크기로 수수료 효율 극대화

### 4. **배치 주문 처리 (Batch Order Placement)**
**목적**: 여러 주문을 한 번의 API 호출로 처리

**구현 방법**:
- 거래소 API가 배치 주문을 지원하는지 확인
- 여러 close 주문을 배치로 한 번에 제출
- API 호출 수 감소로 네트워크 비용 절감

**절감 효과**:
- API 호출 오버헤드 감소
- 일부 거래소에서 배치 주문 시 수수료 할인 가능

### 5. **수수료 인식 그리드 전략 (Fee-Aware Grid Strategy)**
**목적**: 수수료를 고려한 그리드 간격 최적화

**구현 방법**:
- `grid-step`을 수수료 구조에 맞춰 자동 조정
- 수수료를 커버할 수 있는 최소 그리드 간격 계산
- 수수료가 높을수록 그리드 간격 확대

**절감 효과**:
- 수수료를 고려하지 않은 그리드로 인한 손실 방지
- 최소 수익성 있는 그리드 간격 보장

### 6. **강화된 Maker-Only 모드**
**목적**: 모든 주문을 확실히 maker로 만들기

**구현 방법**:
- 주문 가격을 더 보수적으로 설정 (현재보다 더 멀리)
- 주문이 즉시 체결되지 않도록 보장
- 체결 대기 시간 증가로 maker 보장

**절감 효과**:
- 실수로 taker가 되는 경우 방지
- 모든 주문에서 maker 리베이트 확보

### 7. **수수료 추적 및 리포팅**
**목적**: 실제 수수료를 추적하고 최적화

**구현 방법**:
- 각 거래의 수수료 계산 및 기록
- 일일/주간/월간 수수료 리포트 생성
- 수수료 대비 수익률 분석
- 수수료가 예상보다 높은 경우 알림

**절감 효과**:
- 수수료 패턴 파악으로 최적화 포인트 발견
- 비정상적인 수수료 발생 시 조기 감지

### 8. **스마트 주문 라우팅**
**목적**: 최적의 가격 레벨 선택으로 maker 보장

**구현 방법**:
- 오더북 깊이 분석
- 각 가격 레벨에서 maker가 될 확률 계산
- 가장 높은 확률의 가격 레벨 선택
- 시장 깊이를 고려한 동적 가격 조정

**절감 효과**:
- maker 보장률 향상
- 불필요한 주문 취소 및 재제출 감소

### 9. **조건부 주문 최적화**
**목적**: 시장 조건에 따른 주문 전략 조정

**구현 방법**:
- 시장 변동성이 낮을 때: 더 작은 그리드 간격으로 더 많은 주문
- 시장 변동성이 높을 때: 더 큰 그리드 간격으로 안정성 확보
- 스프레드가 넓을 때: maker 확률이 높은 가격 선택

**절감 효과**:
- 시장 조건에 맞는 최적 전략으로 수수료 효율 향상

### 10. **주문 취소 최소화**
**목적**: 불필요한 주문 취소로 인한 수수료/시간 낭비 방지

**구현 방법**:
- 주문 취소 전에 체결 가능성 재평가
- 취소가 필요한 경우에만 취소
- 주문 수정 기능 활용 (거래소 지원 시)

**절감 효과**:
- 주문 취소로 인한 시간 손실 감소
- 더 많은 주문이 체결되어 볼륨 증가

## 구현 우선순위

### 높은 우선순위 (즉시 효과)
1. **수수료 추적 및 리포팅** - 현재 수수료 상황 파악 필수
2. **강화된 Maker-Only 모드** - 실수로 taker가 되는 것 방지
3. **수수료 인식 그리드 전략** - 수수료를 고려한 최소 간격 보장

### 중간 우선순위 (중기 효과)
4. **스마트 주문 집계** - 주문 관리 효율화
5. **동적 주문 크기 최적화** - 최적 주문 크기로 수수료 절감
6. **스마트 주문 라우팅** - maker 확률 향상

### 낮은 우선순위 (장기 효과)
7. **배치 주문 처리** - 거래소 API 지원 필요
8. **Maker 수수료 리베이트 최적화** - 리베이트 프로그램 분석 필요
9. **조건부 주문 최적화** - 복잡한 시장 분석 필요
10. **주문 취소 최소화** - 기존 로직 개선

## 예상 절감 효과

- **Maker-Only 강화**: Taker 수수료 발생 방지로 **0.02-0.05%** 절감
- **주문 집계**: 주문 관리 효율화로 **5-10%** 간접 절감
- **그리드 최적화**: 수수료를 고려한 간격으로 **10-20%** 수익성 향상
- **수수료 추적**: 패턴 분석으로 **5-15%** 추가 최적화 가능

**총 예상 절감**: 현재 대비 **20-50%** 수수료 절감 가능
